## 1. 배경 --- 사용자 작성

지금까지 구현한 일본어 공부 백엔드/프론트엔드를 그대로 사용해서 영어 단어 공부를 하는 기능을
추가하고 싶다. 어플 이름이나 다른 것들이 `nihongo` 이런 식으로 일본어 공부처럼 나와 있긴 한데
어차피 나 혼자 쓸 거라서 그냥 무시하고 영어 학습 기능도 추가하면 된다.

난이도 및 대상 수준은 한국의 정규 교육과정을 따른 사람인데, 막 원어민이랑 대화는 불가능하지만
기본적인 영어회화는 가능한 수준이다. 토익 700후반, 오픽 IM2인데 내가 원하는 것은 시험을 잘 보는
것이 아니라, 원어민과 대화를 할 수 있고 미국 드라마를 볼 때 혹은 팟캐스트를 들을 때 이해도를
높이는 것이 목적이다.

실제로 연구결과에 따르면 영어 단어/구문을 3000개 정도만 알면 드라마와 일상대화의 95%를 이해할 수
있다고 한다. 즉, 내가 원하는 것은 토플이나 아이엘츠처럼 어렵고 복잡한 영어 단어가 아니라
'실생활에서 살아남기 위한 생존영어'에 가깝다.

이미 수능도 봤고 영어로 진행하는 전공 수업도 들었지만 실제로는 대화가 어렵다. 예를 들어 `you`가
뭔지도 알고 `good`이 뭔지도 알지만, 미국 여행 갔을 때 외국인이 문제가 생긴 나한테 `you good?`
이라고 물어봤는데 뭔 소리인지 몰랐다.

지금 만들어 놓은 반복 학습 알고리즘 및 GPT로 구문 및 설명 생성하는 기능을 알차게 사용하고 싶다.

## 2. 원하는 것 --- 사용자 작성

-   실제 쓰이는 영어 단어 및 표현을 공부하고 싶다.
-   학습 방법 자체는 일본어 학습 체계를 똑같이 따라가면 된다.
-   완전히 새로운 어플을 개발하는 것이 아니라 그냥 기능만 추가한다.
-   사용자 입장에서는 맨 처음 화면에서 영어 공부 할지 일본어 공부할지 선택할 수 있게 하면 된다.
-   지금 당장은 바로 만들라는 것이 아니고, **명세 문서들을 대대적인 수정 및 추가를 먼저 진행**해서
    차근차근 영어 학습 가능하게 만드는 것이 목표다.

### 결정 사항 (2026-10-01, 질문에 대한 답)

| # | 주제 | 결정 |
|---|---|---|
| D-1 | 언어 분리 | `learning_items` / `sentences`에 **`language` 컬럼 추가**. 계정은 하나 |
| D-2 | 첫 화면 | **언어 먼저 고르고 언어별 홈으로** 간다 |
| D-3 | 소리 | **브라우저 내장 TTS 추가** |
| D-4 | 듣기의 지위 | **재생 버튼만. 학습 신호가 아니다** |
| D-5 | seed 출처 | **공개 빈도자료로 선별 + LLM으로 예문·설명 생성 후 검수** |
| D-6 | seed 규모 | **1차 300표현 / 문장 약 1000** |
| D-7 | item 타입 | **기존 3종 유지.** 구동사·관용구·슬랭은 태그로 구분 |

## 3. 원하지 않는 것 --- 사용자 작성

-   완전히 새로운 앱을 만드는 것.
-   앱 이름(`Nihongo Context`)이나 저장소 이름을 바꾸는 것. 혼자 쓰니까 신경 쓰지 않는다.
-   학습 알고리즘을 새로 만드는 것. 지금 것을 알차게 재사용한다.
-   시험 어휘(TOEFL·IELTS 수준의 어렵고 복잡한 단어).
-   지금 당장 구현을 시작하는 것. 명세가 먼저다.

## 4. 참고 --- 사용자 작성

-   `you good?` 사례 --- 미국 여행 중 실제로 못 알아들은 표현.
-   "3000 단어면 드라마·일상대화 95% 이해"라는 연구 결과.
    (Claude 확인: Nation 2006의 **단어족** 기준 수치다. 표현 단위 seed에 그대로 적용되지
    않으므로 명세·README·UI에 커버리지 퍼센트를 적지 않기로 했다.)
-   관련 요청: U-001(선택 홈), U-005(demo 확장) --- 둘 다 이번에 영향을 받는다.

## 5. 완료 확인 방법 --- 사용자 작성

-   첫 화면에서 일본어와 영어를 고를 수 있다.
-   영어를 골라 로그인하면 일본어와 같은 방식으로 학습이 돌아간다.
-   나오는 표현이 `you good?` 같은 종류다. 시험 단어가 아니다.
-   설명을 읽고 "그때 이걸 알았으면 알아들었겠다"는 느낌이 든다.
-   **일본어 학습이 지금과 똑같이 돌아간다.** 기존 학습 기록이 사라지지 않는다.

## 6. 영향 명세·충돌 --- Claude 작성

### 영향 범위

**MVP-02보다 넓다.** 컬럼 리네임과 route 변경이 이미 운영에서 도는 일본어 학습 전체를 지나간다.
수정한 문서 전체 목록은 `spec/mvp-03-english/00_SCOPE.md`의 `수정하는 기존 문서`에 있다.

``` text
신설   spec/mvp-03-english/{00_SCOPE, 01_ENGLISH_CONTENT, 12_TEST_PLAN, 13_ACCEPTANCE_CRITERIA}.md
       docs/decisions/ADR-023 (다언어 모델) · ADR-024 (영어 콘텐츠) · ADR-025 (홈·route·TTS)
수정   spec/00~06 전부, spec/mvp-01-core/ 거의 전부, AGENTS.md, README.md, .gitignore
```

### 찾은 충돌과 해소

1.  **`updates/README.md`가 요구하는 "요청 → 영향 분석 → 결정 → spec-sync"에서 결정이 먼저
    필요했다.** 구현 전에 사용자에게 10가지를 물었고 전부 답을 받았다(위 표). 요청서는 그
    결정을 기록한 것이다.
2.  **MVP-01 `00_SCOPE.md`의 "Audio 일체가 MVP-01 범위 밖이다"와 D-3이 정면으로 충돌한다.**
    → 다섯 줄 중 `TTS 없음`과 `audio button 없음` **두 줄만** 해제하고 나머지 셋(audio API,
    audio event, listening review)은 유지했다. `AGENTS.md`의 금지 목록에도 같은 부분 해제를
    적었다.
3.  **ADR-025 초안이 `03_UI_UX_SPEC.md`의 `완료 화면`과 충돌했다.** 초안은 완료 화면에
    `다른 언어로` 버튼을 두려 했으나, 그 절이 **"새 세션 시작 버튼을 두지 않는다"**를 이미
    금지하고 있다(세션 행이 부풀고 압박이 된다). → **초안을 철회했다.** 세션을 끝낸 뒤 앱
    이름 → 언어 선택 홈 → `로그인`을 누르면 열린 세션이 없으므로 언어 선택 화면이 자연히
    나온다. 새 UI가 필요 없다.
4.  **`04_DB_SPEC.md`의 `알려진 공백 --- 추가 적재 의미론이 없다`가 이 요청의 전제 조건이었다.**
    현재 loader는 seed 행이 있으면 적재를 전부 거부하고 운영 DB는 reset하지 않으므로,
    **그것을 해소하지 않으면 영어 seed를 넣을 수 없다.** → `seed_id` 안정 키와 `--incremental`
    모드를 명세에 넣어 해소했다(ADR-023 결정 4).
5.  **`content.max_sentence_length_chars: 60`이 일본어에 맞춘 값이다.** 영어 구어 문장은 60자를
    거의 다 넘는다. → 언어별 맵으로 바꿨다. **config 로더 변경이고 production override 전체
    사본을 다시 만들어야 한다.**
6.  **`normalized_hash`가 "모든 공백 제거"다.** 영어에 쓰면 대소문자만 다른 중복이 통과하고
    단어 경계가 사라진다. → 언어별 규칙으로 나누고 **일본어 규칙은 한 글자도 바꾸지
    않았다**(기존 765문장의 해시가 깨지면 duplicate 검사가 seed를 못 본다).
7.  **브라우저 TTS가 격리 검사 (f)와 충돌할 수 있다.** Chrome의 일부 음성은 **외부 서버에서**
    합성되므로 "frontend origin 밖 요청 0건"이 깨진다. → `voice.localService === true`인 음성만
    쓰기로 했다. 검사를 느슨하게 고치지 않는다(ADR-025 결정 4).
8.  **`users.starting_level`이 계정에 하나뿐이다.** 일본어 초급 / 영어 중급을 표현할 수 없다.
    → **이번에 고치지 않고 알려진 공백으로 기록**했다. 유일한 소비처가 생성 프롬프트이고,
    고치려면 새 컬럼이나 새 테이블이 필요한데 둘 다 실사용 후 판단할 값이다.

### 새 불변식

21\~28을 추가했다. 목록은 `spec/mvp-03-english/00_SCOPE.md`의 `추가 불변식 (MVP-03)`.

## 7. 결정 필요 질문 --- Claude 작성

**없음.** 10가지를 물었고 전부 답을 받았다(위 D-1\~D-10). 남은 미정 항목은 "지금 결정하지
않기로 한 것"이며 `spec/mvp-03-english/00_SCOPE.md`의 `알려진 공백`에 사실로 기록했다.

구현 착수 전에 사용자가 해야 하는 일은 하나뿐이다.

-   **1차 300표현 목록의 사람 확인**(선별 5단계). "이건 이미 안다"를 걷어낸다. LLM 난이도
    분류는 추정이고 이 단계가 유일한 사실 확인이다.

## 8. 작업 계획 --- Claude 작성

| Wave | 방식 | 내용 |
|---|---|---|
| 0 | 직렬, main | **(완료)** 외부 자료 확보, 결정 수집, ADR-023·024·025, `spec/mvp-03-english/` 신설, 기존 명세 제자리 수정, 이 요청서 |
| 1 | 직렬, main | DB migration(리네임·`language`·`seed_id`·제약) + 모델. **운영 DB에 닿지 않는다** |
| 2 | 직렬, main | 리네임 전파 --- 모델·API·LLM 스키마·seed 파일·프론트·테스트의 기계적 수정. 여기서 기존 테스트가 전부 다시 녹색이 되어야 한다 |
| 3 | 병렬 레인 | `engine-lang`(언어 범위·세션 언어·409) · `seed-infra`(증분 적재·`backfill_seed_id`·언어별 정규화) · `prompt-lang`(언어별 prompt·validation 14) |
| 4 | 직렬, main | 영어 seed 생성과 검수 --- `build_en_seed.py`, 300표현 선별, LLM 예문·설명, **사용자 확인**, `seed/en/*.yaml` 커밋 |
| 5 | 병렬 레인 | `home-route`(언어 선택 홈·중첩 route·리다이렉트) · `demo-en`(영어 fixture·진도 key 분리) · `speech`(재생 버튼) |
| 6 | 직렬, main | 배포 절차 문서(`infra/DEPLOY.md`: migration → `backfill_seed_id` → prompt 등록 → 영어 seed 적재 → config 사본 재작성), README, 상태 갱신 |

-   **Wave 2가 가장 위험하다.** 40개 넘는 파일의 기계적 수정이지만, 빠뜨리면 조용히 통과하는
    것이 아니라 컴파일·수집 단계에서 실패한다. 그 점이 안전장치다.
-   **Wave 1\~2는 쪼개지 않는다.** 리네임이 끝나기 전에 레인을 열면 모든 레인이 같은 파일에서
    충돌한다.
-   Wave 3 머지 순서: `seed-infra` → `prompt-lang` → `engine-lang`.
-   Wave 5 머지 순서: `home-route` → `demo-en` → `speech`.
-   **배포는 사용자가 한다.** 순서가 있다: schema migration → `backfill_seed_id` → prompt 등록
    → 영어 seed 증분 적재 → config override 사본 재작성 → API·worker 재시작 → frontend 배포.
    `backfill_seed_id`가 먼저여야 증분 적재가 기존 일본어 행을 "이미 있다"고 올바로 판단한다.
-   게이트는 MVP-02와 같다: scope-guard, security-reviewer, learning-verifier, test-engineer,
    db-migration(Wave 1).
