# guitar-riff 전환 관찰 기록

| 항목 | 값 |
|---|---|
| 대상 | `https://guitar-riff.pages.dev/` |
| 관찰일 | 2026-09-13 |
| 받은 것 | 홈 HTML, 커리큘럼 상세 1개(`/c/<id>/`), 레슨 상세 1개(`/c/<id>/m1/w1/d1/`), 도구 페이지 1개(`/tools/metronome/`), 공용 CSS 2개, 공용 JS 번들 2개, 동적 import 조각 2개 |
| 방법 | `curl`로 받아 CSS 규칙과 JS 이벤트 처리를 읽음. 브라우저에서 실행해 보지 않았다(실측 없음) |
| 저장 위치 | 받은 원본은 세션 scratchpad에만 두었다. 저장소에 넣지 않는다 |

이 문서는 **값과 패턴만** 우리 말로 적는다. 코드·이미지·문구를 옮기지 않는다.

---

## 1. 구조 한눈에 보기

- 여러 페이지로 된 정적 사이트다. 페이지 사이 이동은 **클라이언트 라우터가 가로채서 본문만 바꿔
  끼우는** 방식이다(Astro의 client router).
- 라우터는 브라우저가 지원하면 **View Transitions API(`document.startViewTransition`)** 로 교체를
  감싼다. 지원하지 않으면 "animate" 대체 모드로 표시된다.
- 요소마다 이름을 붙인 전환(`view-transition-name`, 공유 요소 전환)은 **없다.** 페이지 단위
  기본 교차 페이드만 쓴다.
- 애니메이션 라이브러리는 없다. 움직임은 전부 **CSS transition / @keyframes** 이고, JS는 클래스를
  붙였다 뗄 뿐이다. 예외는 축하용 종이 조각(canvas) 하나다.

## 2. 무엇이 움직이나 (관찰값)

### 2.1 화면(페이지) 전환

| 무엇 | 방식 | 값 |
|---|---|---|
| 페이지 전체 | View Transitions 기본 교차 페이드(옛 화면 사라짐 + 새 화면 나타남) | 사이트가 duration·easing을 **지정하지 않았다.** 브라우저 기본값을 따른다(명세상 0.25초 `ease`로 알려져 있으나 실측은 확인 못 함) |
| 새 화면의 내용 블록 | 본문 컨테이너의 직계 자식이 아래에서 살짝 떠오르며 나타남 | 투명 → 불투명, 아래 10px → 제자리, **0.4초 `ease`**, 채움 모드 both |
| 내용 블록 순차 지연 | 2·3·4번째 자식에만 지연 | **30ms 간격**(0.03 / 0.06 / 0.09초). 5번째부터는 지연 없음 |
| 스크롤 | 새 페이지로 가면 맨 위로 **즉시**(부드러운 스크롤 아님) 이동. 뒤로 가기는 저장한 위치를 복원 | - |
| 미지원 브라우저 | 이름 붙은 전환이 없으므로 사실상 즉시 교체로 보일 것으로 추정 | 확인 못 함 |

요점: **나가는 화면은 애니메이션하지 않고, 들어오는 화면만 짧게 떠오른다.** 방향(앞/뒤)에 따라
다르게 움직이지 않는다. 좌우 슬라이드가 없다.

### 2.2 바텀시트

| 무엇 | 방식 | 값 |
|---|---|---|
| 배경 가림막(scrim) | 화면 전체를 덮는 고정 레이어. 투명도만 바뀜 | 검정 약 42% 투명도, **0.28초**(easing 미지정 = `ease`) |
| 시트 본체 | 화면 아래 밖에서 위로 올라옴(`translateY(100%)` → 0) | **0.34초 `cubic-bezier(.2,.9,.25,1)`** (빠르게 출발해 부드럽게 멈추는 감속 곡선) |
| 열기/닫기 | 가림막에 표시 클래스 하나를 붙였다 뗌. 가림막과 시트가 같은 클래스로 함께 움직임 | 닫을 때도 같은 duration으로 역재생 |
| 닫는 방법 | 가림막 빈 곳 탭, 시트 안의 닫기 버튼 | 아래로 끌어 닫기(드래그)는 **없음**. Esc 키 처리와 포커스 이동도 코드에서 **찾지 못함** |
| 모양 | 위 모서리만 둥근 시트(반경 28px), 위쪽 가운데 손잡이 막대(40×4px), 최대 높이 화면의 88%, 넘치면 시트 안에서 스크롤, 아래 여백에 안전 영역 더함 | - |
| 떠 있는 변형 | 도구 시트는 네 모서리 모두 둥글고 좌우·아래에 12px 띄움 | 최대 높이 86% |
| 접근성 속성 | `role="dialog"`, `aria-modal="true"`, 제목 연결 | - |

### 2.3 카드와 버튼의 누름 반응

**hover 효과가 거의 없다.** 모바일 기준이라 `:active`(누르는 동안)만 반응한다. 탭 하이라이트 색은
투명으로 끈다.

| 대상 | 누를 때 | transition |
|---|---|---|
| 큰 카드(목록 카드) | `scale(.985)` | transform 0.12초 `ease`, 그림자 0.15초 |
| 기본 버튼(높이 56px, 꽉 찬 너비) | `scale(.98)` + 배경을 진한 색으로 | transform 0.1초, 배경 0.15초 |
| 작은 기능 카드(4열 격자) | `scale(.97)` + 배경 옅게 | transform 0.12초 `ease` |
| 떠 있는 둥근 버튼(FAB) | `scale(.94)` | transform 0.12초 `ease` |
| 목록 행(레슨 한 줄) | `scale(.99)` + 배경 옅게 | transform 0.1초, 배경 0.15초 |
| 아이콘 버튼 | 배경만 옅은 회색 | 0.15초 |
| 텍스트 링크형 뒤로 버튼 | 투명도 0.6 | 지정 없음 |
| 비활성 카드(아직 열리지 않은 기능) | 누름 반응을 끔 | - |

규칙이 보인다: **요소가 작을수록 더 많이 줄어든다**(.99 → .985 → .98 → .97 → .94).

### 2.4 그 밖의 움직임

| 무엇 | 방식 | 값 |
|---|---|---|
| 토스트 | 화면 아래에서 올라오며 나타남(`translateY(140%)` → 0 + 투명도) | transform **0.4초 `cubic-bezier(.2,.9,.25,1)`**, 투명도 0.3초. **7초 뒤 자동으로 사라짐**, 탭하면 바로 닫힘, 사라진 뒤 0.4초 후 DOM에서 제거 |
| 세그먼트 탭 전환(패널) | 새 패널이 아래 8px에서 떠오름 + 투명도 | **0.28초 `cubic-bezier(.2,.9,.25,1)`** |
| 세그먼트 버튼 선택 표시 | 선택된 칸이 흰 배경 + 작은 그림자로 바뀜 | 0.15~0.18초 |
| 진행바 | 너비 변화 | **0.6초 `cubic-bezier(.2,.8,.2,1)`** |
| 아코디언(월/주 펼치기) | 내용은 **즉시** 보였다 숨김(높이 애니메이션 없음). 화살표만 180도 회전 | 회전 0.25초 |
| 체크 표시(완료) | 원 테두리 → 초록 채움 | 0.2초 |
| 입력 필드 포커스 | 테두리 색 + 배경 | 0.15초 |
| 상단바 | 화면에 붙어 있고(sticky, 높이 56px) 반투명 배경 + 흐림. 스크롤이 4px을 넘으면 아래 경계선이 나타남 | 경계선은 transition 없음 |
| 테마 전환 | 배경·글자색 | 0.25초 `ease` |
| 필터 칩으로 목록 바꾸기 | View Transitions로 감싸 교차 페이드 | 브라우저 기본값 |
| 축하 연출 | 이미지가 작게 튀어 오르며 커짐(살짝 넘쳤다 돌아오는 곡선), 글자는 0.28초 늦게 튀어나옴, canvas 종이 조각 | 0.5초 `cubic-bezier(.22,1.3,.36,1)`, 0.55초 `cubic-bezier(.2,1.4,.4,1)` |
| 재생 중 표시 | 막대 3개가 위아래로 반복 | 0.9초 무한 반복, 0.15초씩 어긋남 |

### 2.5 `prefers-reduced-motion`

- **전역 규칙 하나**로 모든 요소의 animation을 0.001ms, transition을 0.01ms로 줄인다(`!important`).
  사실상 "즉시 상태 변경"이다. 투명도 페이드도 함께 사라진다.
- 튀어 오르는 축하 이미지와 반복 막대는 **별도로 animation을 끈다.** 반복 막대는 멈춘 중간 높이로
  고정한다.
- canvas 종이 조각은 JS에서 미디어 쿼리를 확인해 **아예 그리지 않는다.**
- View Transitions 교차 페이드에 대한 별도 처리는 찾지 못했다(전역 규칙이 의사 요소에도 적용되는지는
  확인 못 함).

## 3. 레이아웃·여백·카드·문구 톤의 특징

**레이아웃**
- 앱 본문은 **최대 480px 한 칼럼**이다. 600px 이상 화면에서는 가운데 떠 있는 카드처럼 보인다(위아래
  24px 띄움, 반경 28px, 그림자). 레슨 화면만 720px까지 넓어진다.
- 바깥 배경은 옅은 회색, 앱 본문은 흰색이다.
- 본문 좌우 여백 20px, 아래 32px. 카드 사이 간격 14~16px.

**카드**
- 흰 배경 + 1px 옅은 경계선 + 반경 20px + 안쪽 여백 20px. **카드 자체에는 그림자를 거의 쓰지 않고**
  경계선으로 구분한다.
- 작은 요소는 반경 14px, 알약 모양(999px) 칩을 많이 쓴다.
- 강조 영역은 테두리 없이 옅은 주 색 배경으로 채운다.

**글자**
- 큰 제목 30px·굵기 800·자간을 좁게(-0.035em). 섹션 제목 20px·800. 본문 15~16px, 보조 문구는 한
  단계 옅은 회색.
- 한국어 줄바꿈은 단어 단위(`keep-all`)를 쓰는 곳이 있다.

**색**
- 회색 단계 10개와 파란 주 색 하나, 보조로 초록(완료)·빨강(경고)·노랑.
- 다크 테마가 있다.

**문구 톤**
- 전부 해요체. 한 문장이 짧고, 한 문장에 한 가지만 말한다.
- 부담을 먼저 덜어 준다: 가입이 필요 없다는 점, 진도가 어디에 저장되는지, 저장이 사라질 수 있는 경우와
  그때 할 수 있는 대비를 차례로 짧게 알려 주는 흐름.
- 미루기·거절 버튼을 부드러운 말로 쓴다. 잠긴 항목에는 곧 열린다는 짧은 안내를 붙이고, **탓하지 않고
  앞으로 할 일**로 말한다.
- 완료 순간에 짧은 칭찬 한 줄을 토스트로 띄운다. 이모지를 섞는다(우리는 이모지를 쓰지 않는다).

## 4. 확인 못 한 것

- 실제 브라우저에서 돌려 본 체감·프레임. 전부 코드에서 읽은 값이다.
- View Transitions 교차 페이드의 실제 duration·easing(사이트가 지정하지 않아 브라우저 기본값).
- View Transitions를 지원하지 않는 브라우저에서의 모습.
- 전역 reduced-motion 규칙이 View Transitions 의사 요소에도 걸리는지.
- 시트의 포커스 이동·Esc 닫기·배경 스크롤 잠금(코드에서 찾지 못했다 → 없는 것으로 보이지만 단정하지
  않는다).

## 5. Nihongo Context 적용안

### 5.1 판단

- **vanilla CSS만으로 충분하다.** 관찰한 움직임은 전부 CSS transition·@keyframes와 클래스 토글이다.
  프레임워크·애니메이션 라이브러리가 필요하지 않다. 따라서 "참고 사이트 방식을 따르려면 프레임워크나
  라이브러리가 필요하면 멈추고 보고한다"는 조건(`updates/done/U-001-ui-ux-overhaul/request.md` 7절)에 해당하지
  않는다.
- **View Transitions API는 쓰지 않는다(Wave 2 기준).** 이유:
  - 우리 앱은 한 문서 안에서 `replaceChildren`으로 화면을 바꾼다. 들어오는 화면의 CSS 진입 애니메이션
    만으로 guitar-riff의 체감(짧은 페이드 + 살짝 떠오름)을 같게 만들 수 있다.
  - 교차 페이드와 진입 애니메이션을 함께 쓰면 움직임이 두 겹이 된다.
  - 지원 여부에 따라 모양이 갈리고, e2e에서 전환 중 스냅샷이 흔들릴 여지가 생긴다.
  - 나중에 넣고 싶다면 `document.startViewTransition`이 있을 때만 화면 교체를 감싸고, 그때는 CSS 진입
    애니메이션을 끄는 식으로 **둘 중 하나만** 쓴다.

### 5.2 motion 토큰

`frontend/src/styles.css`의 `:root`에 둔다(이름은 제안).

| 토큰 | 값 | 쓰는 곳 | 근거(관찰) |
|---|---|---|---|
| `--motion-fast` | `120ms` | 누름 반응, 색·배경 변화, 토글 스위치 | 누름 0.1~0.12초, 색 0.15초 |
| `--motion-base` | `240ms` | 가림막 페이드, 탭·패널 전환, 토스트 투명도 | 가림막 0.28초, 패널 0.28초 |
| `--motion-slow` | `360ms` | 화면 진입, 시트 올라오기, 토스트 올라오기, 진행바 | 진입 0.4초, 시트 0.34초, 토스트 0.4초 |
| `--ease-out` | `cubic-bezier(.2, .9, .25, 1)` | 움직이는 것(시트·토스트·화면 진입·진행바) | 시트·토스트·패널에 공통 |
| `--ease-standard` | `ease` | 색·투명도·누름 반응 | 대부분의 짧은 transition |

튀어 오르는(overshoot) 곡선은 **들이지 않는다.** 학습 앱에서 축하 연출은 압박으로 읽힐 수 있고,
세션 종료에 연출을 붙이지 않는 규칙(overdue/streak 압박 금지)과 같은 취지다.

### 5.3 규칙

**화면 전환**
- 새 화면의 최상위 요소에 진입 클래스를 붙인다: 투명도 0 → 1, 아래 12px → 제자리,
  `--motion-slow` `--ease-out`.
- 나가는 화면은 애니메이션하지 않고 바로 뗀다(DOM이 두 벌 겹치지 않는다).
- 앞/뒤 방향으로 다르게 움직이지 않는다. 좌우 슬라이드를 쓰지 않는다.
- 순차 지연은 홈 카드처럼 **나란한 카드 2~3개에만** 30ms 간격으로 쓴다. 학습 화면의 문장·버튼에는
  쓰지 않는다(읽기 시작이 늦어진다).
- 화면을 바꾸면 스크롤을 맨 위로 즉시 옮기고, 새 화면의 제목(`tabindex="-1"`)에 포커스를 둔다.
- 학습 화면 안에서 **다음 문장으로 넘어갈 때**는 문장 영역에만 `--motion-base` 페이드를 쓴다. 떠오름
  이동은 넣지 않는다(매 문장마다 움직이면 피로하다).

**바텀시트 (설명·문장 뜻·확인)**
- 가림막 투명도 0 → 1 `--motion-base`, 시트 `translateY(100%)` → 0 `--motion-slow` `--ease-out`.
  닫을 때 같은 값으로 되돌리고, 끝나면 `hidden`으로 숨긴다.
- **시트 내용은 열 때 만든다.** 번역은 reveal 응답을 받은 뒤에 노드를 만든다. 숨겨 둔 번역 노드를
  미리 두고 시트로 보여주는 구조로 만들지 않는다(기존 `ui/interactions.ts` 규칙 유지).
- 닫는 방법 셋: 가림막 탭, `닫기` 버튼, Esc. guitar-riff에 없던 **포커스 이동**을 더한다: 열면 시트
  제목으로, 닫으면 시트를 연 요소로 돌려준다.
- 시트가 열려 있어도 문장은 위쪽에 보이게 시트 최대 높이를 화면의 **70%** 로 둔다(guitar-riff 88%보다
  낮춤). 넘치면 시트 안에서 스크롤한다.
- 위 모서리 반경 20px, 손잡이 막대는 장식이다(드래그 닫기는 만들지 않는다).
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby`.
- 자기평가 버튼은 시트 아래쪽(엄지가 닿는 곳)에 둔다. 누르지 않고 닫아도 된다.

**카드·버튼 누름**
- 큰 카드 `scale(.98)`, 버튼 `scale(.97)`, 작은 칩·표 칸 `scale(.95)`. `--motion-fast` `--ease-standard`.
- `:active`에만 반응한다. hover 효과는 두지 않는다(데스크톱에서도 커서 변화만).
- `-webkit-tap-highlight-color: transparent`로 기본 탭 하이라이트를 끄고, 대신 **`:focus-visible`
  윤곽선을 반드시 둔다**(키보드 사용자).
- `disabled`는 누름 반응을 끈다.
- tappable 표현(토큰)은 크기를 줄이지 않는다. 문장 줄바꿈이 흔들린다. 배경색 변화만 `--motion-fast`.

**토스트·안내**
- 쓰는 곳: 한 번 사라지는 **정보성** 안내만. 예: 세션 시작 안내(`이어서 학습해요`), `기록했어요`,
  `진도를 초기화했어요`.
- 화면 아래(다음 문장 버튼 위)에서 올라온다: 아래 16px → 제자리 + 투명도, `--motion-base` `--ease-out`.
- **4초 뒤 사라진다**(guitar-riff 7초보다 짧음 — 문장이 한 줄이다). 탭하면 바로 닫힌다.
  `role="status"`.
- **오류는 토스트로 띄우지 않는다.** 사라지면 사용자가 놓치고, 재시도 버튼을 붙일 수 없다. 오류는
  해당 자리에 인라인으로 남기고 할 수 있는 행동 버튼을 붙인다(기존 `renderNotice` 규칙 유지).
- 안내가 학습 진행을 막지 않는다(기존 `세션 시작 안내` 규칙).

**진행바**
- 너비 변화 `--motion-slow` `--ease-out`. 진행은 문장 단위로만 갱신되므로 한 번에 한 칸씩 부드럽게
  늘어난다(주기적 갱신을 만들지 않는다는 기존 규칙과 무관하게 동작).

**후리가나 토글**
- 스위치 손잡이 이동과 색 변화 `--motion-fast`. ruby를 켜고 끌 때 **문장에는 애니메이션을 주지
  않는다**(줄 높이가 바뀌어 글자가 튀어 보인다).

### 5.4 reduced-motion 대체

`@media (prefers-reduced-motion: reduce)` 안에서:

| 대상 | 기본 | 줄였을 때 |
|---|---|---|
| 화면 진입 | 페이드 + 12px 떠오름 | **페이드만** `--motion-fast` |
| 시트 | 아래에서 올라옴 | **이동 없이 페이드만** `--motion-fast`(가림막 포함) |
| 토스트 | 올라옴 + 페이드 | 페이드만 |
| 카드·버튼 누름 | scale | **scale 없음**, 배경색 변화만 |
| 진행바 | 너비 transition | 즉시 |
| 순차 지연 | 30ms | 없음 |

- guitar-riff처럼 전역으로 0에 가깝게 누르는 대신 **이동(transform)만 없애고 짧은 페이드는 남긴다.**
  페이드는 위치 변화가 없어 전정 자극이 거의 없고, 화면이 바뀌었다는 단서를 준다.
- 구현은 토큰을 바꾸는 방식이 가장 적다: 미디어 쿼리 안에서 이동 거리 변수(예: `--motion-shift`)를
  `0`으로, 누름 배율 변수를 `1`로, `--motion-slow`를 `--motion-fast`로 바꾼다.
- e2e는 Playwright의 `reducedMotion: 'reduce'` 에뮬레이션으로 이 분기를 확인할 수 있다.
