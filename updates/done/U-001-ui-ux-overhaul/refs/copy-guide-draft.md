## 1. 우선순위

1. **보안 문구 규칙이 말투보다 먼저다.** 로그인 실패는 사유를 가르지 않는 한 문구다. 말투를 다듬다가
   "없는 아이디"와 "틀린 비밀번호"를 가르게 되면 안 된다.
2. **명세가 고정한 문구와 의미**(probe 4지 라벨, `오늘 학습 완료`, `더 학습하기`, `아직 평가 없음` 등)는
   말투 때문에 뜻을 바꾸지 않는다. 표기를 바꾸려면 spec-sync가 명세를 먼저 고친다.
3. **서버가 준 숫자만 화면에 쓴다**는 규칙은 그대로다. 말투를 다듬으면서 분 수·횟수를 새로 적지 않는다.
4. 그다음이 아래 원칙 6개다.

## 2. 원칙 6개

### 원칙 1. 해요체

문장은 `~해요`, `~예요`, `~있어요`로 끝낸다. `~합니다`, `~한다`, 명사로 끝나는 안내문을 쓰지 않는다.
버튼·라벨처럼 짧은 이름은 명사형(`다음 문장`, `로그아웃`)이나 `~하기`(`다시 시도하기`)를 쓴다.

| 좋은 예 | 나쁜 예 |
|---|---|
| 이어서 학습해요. | 이어서 학습합니다. |
| 저장하지 못했어요. 다시 시도해 주세요. | 저장 실패. 재시도하십시오. |
| 아직 학습 기록이 없어요. | 학습 기록 없음 |

예외: 학습 콘텐츠(설명의 `core_meaning`, `nuance` 등)는 seed·LLM이 만든 **데이터**라서 이 가이드의
대상이 아니다. 화면이 조립하거나 고치지 않는다.

### 원칙 2. 한 문장에 한 정보

쉼표·`~며`·`~고`로 두 사실을 잇지 않는다. 필요하면 문장을 나눈다.

| 좋은 예 | 나쁜 예 |
|---|---|
| 체험 중이에요. 기록은 이 브라우저에만 남아요. | 데모 모드이며 실제 계정이 아니고 기록은 이 브라우저에만 저장됩니다. |
| 알려 주셔서 고마워요. 이 문장은 이제 나오지 않아요. | 신고를 접수했으며 이 문장은 앞으로 학습에 사용되지 않습니다. |

### 원칙 3. 짧게

한 문장은 대체로 **25자 안팎**을 넘기지 않는다. 뜻이 같으면 더 짧은 쪽을 고른다. 버튼은 2~6자.

| 좋은 예 | 나쁜 예 |
|---|---|
| 닫기 | 설명 닫기 버튼 |
| 오래된 기록은 여기서 보이지 않아요. | 표시 개수 제한으로 인해 오래된 기록 일부는 표시하지 않았습니다. |

### 원칙 4. 탓하거나 재촉하지 않기

사용자가 잘못했다고 읽히는 말(`잘못`, `오류를 일으켰`, `다시는`), 서두르게 하는 말(`지금 바로`,
`놓치지 마세요`, 연속 일수·밀린 복습 수)을 쓰지 않는다. 기존 overdue/streak 압박 금지와 같은 취지다.
틀린 답에도 사실과 다음 일만 말한다.

| 좋은 예 | 나쁜 예 |
|---|---|
| 정답은 ku예요. 이번 라운드에서 한 번 더 나와요. | 틀렸어요! 더 집중하세요. |
| 한동안 쉬어서 새로 시작해요. 지난 기록은 그대로 있어요. | 오랫동안 활동이 없어 세션이 강제 종료되었습니다. |
| 고르지 않아도 괜찮아요. | 먼저 이해도를 선택해야 합니다. |

### 원칙 5. 전문용어 대신 쉬운 말

화면에 내부 개념어를 드러내지 않는다: `세션` → `학습`, `노출` → `본 횟수`, `요청`/`서버`/`API`
→ `연결`, enum 값(`word`, `grammar`) → 우리말 라벨. 내부 id는 계속 노출하지 않는다.

| 좋은 예 | 나쁜 예 |
|---|---|
| 진행 중인 학습이 없어요. | 열린 세션이 없습니다. |
| 본 횟수 3회 | 노출 3회 |
| 지금 연결이 원활하지 않아요. | 5xx 응답 / Transient error |

예외: 학습 도메인의 이름(`후리가나`, `히라가나`, `탁음`, `요음`)은 배우는 대상 자체라서 그대로 쓴다.

### 원칙 6. 할 수 있는 행동을 알려주기

안내·오류 끝에는 사용자가 할 수 있는 일을 적거나 버튼을 붙인다. 할 수 있는 일이 없으면 그 사실을
적는다(무한 대기처럼 보이게 하지 않는다 --- 기존 `ui/notice.ts` 규칙).

| 좋은 예 | 나쁜 예 |
|---|---|
| 지금 연결이 원활하지 않아요. 잠시 후 다시 시도해 주세요. [다시 시도하기] | 알 수 없는 문제가 생겼습니다. |
| 문장 뜻을 불러오지 못했어요. 다시 눌러 주세요. | 문장 뜻을 표시하지 못했습니다. |
| 지금은 준비된 문장이 없어요. 잠시 후 다시 시도해 주세요. [다시 시도하기] | 준비된 문장 없음 |

## 3. 보안·명세 고정 문구 표시

아래 표의 `구분` 열.

| 표시 | 뜻 |
|---|---|
| **보안** | 의미를 반드시 유지한다. 말투만 바꿀 수 있고, 사유를 가르거나 정보를 더하면 안 된다 |
| **명세 고정** | 현재 명세가 문구나 라벨을 고정했다. 바꾸려면 spec-sync가 명세를 먼저 고친다. 표기 그대로 두자는 제안이면 `유지`로 적었다 |
| **서버 값** | 서버 payload나 서버 숫자에서 온다. 화면이 문구를 새로 쓰지 않는다 |
| (빈칸) | 일반 문구 |
