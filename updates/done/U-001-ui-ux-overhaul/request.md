## 1. 배경 --- 사용자 결정 (2026-09-13)

-   이 사이트의 방문자는 사용자의 포트폴리오에서 대표 빌드를 구경하러 오는 사람이다.
-   로그인은 사용자 한 명만 쓴다.
-   현재 첫 화면은 로그인이다. 첫 화면을 로그인 대신 선택 홈으로 바꾸고, 로그인은 상단의 작은
    진입점으로 옮긴다.
-   전 화면을 친절한 말투와 부드러운 전환으로 개편한다.

## 2. 원하는 것 --- 사용자 결정 (2026-09-13)

### 선택 홈 (`#/` 또는 hash 없음)

-   구성: 상단바(`Nihongo Context` + 오른쪽 작은 `로그인`), 한 줄 소개, 카드 2개
    -   표현 학습 체험해 보기 → 기존 demo
    -   글자부터 배우기 → 가나 학습(`U-004`)
-   방문자가 무슨 앱인지 바로 알 수 있어야 한다.

### 서버 요청 규칙

-   홈·demo·가나 학습은 서버 요청 0건이다.
-   이 세 route는 `api.ts`, `endpoints.ts`, `env.ts`를 transitively import하지 않는다.
-   기존 demo 격리 테스트의 방식을 이 세 route로 넓힌다.

### 로그인 흐름

-   상단 `로그인`을 **누를 때만** 로그인 상태를 확인한다(`fetchMe`).
    -   로그인되어 있으면 → 학습 화면
    -   401이면 → 로그인 폼
-   홈을 열 때 자동으로 확인하지 않는다.

### 말투 ('토스체', 말투만 해당)

-   spec-sync가 문구 가이드를 명세에 둔다.
-   원칙
    -   해요체
    -   한 문장에 한 정보
    -   짧게
    -   사용자를 탓하거나 재촉하지 않기
    -   전문용어 대신 쉬운 말
    -   할 수 있는 행동을 알려주기
-   좋은 예와 나쁜 예를 함께 둔다.
-   기존 모든 화면 문구에 적용한다.
-   **보안 문구 규칙은 말투보다 우선한다.** 예: 로그인 실패는 사유를 가르지 않는 한 문구.

### 화면 전환

-   참고 절의 사이트를 따른다.
-   먼저 그 사이트의 HTML/CSS/JS를 받아 전환 패턴을 **관찰해 기록**한다.
    -   기록할 것: 무엇이 움직이는지, duration, easing, 화면 전환·시트·카드·버튼 반응 방식
    -   기록 위치: `refs/guitar-riff-motion.md`, 우리 말로 요약
-   구현은 **자체 CSS**로 한다.
-   설명창과 뜻 확인은 아래에서 부드럽게 올라오는 시트로 한다.
-   화면 사이 이동은 부드럽게 전환한다.
-   `prefers-reduced-motion`이면 움직임을 최소화한다.

### 불변식 (MVP-02 추가 불변식 13·14)

-   13\. 홈·demo·가나 학습은 서버 요청 0건이다. API 모듈을 import하지 않는다.
-   14\. 로그인 상태 확인은 사용자가 로그인 진입점을 누를 때만 한다.

## 3. 원하지 않는 것 --- 사용자 결정 (2026-09-13)

-   회원가입·비밀번호 재설정·소셜 로그인은 계속 없다.
-   로그인 폼, 쿠키, 401 단일 문구, password 규칙(16 code point)을 바꾸지 않는다.
-   참고 사이트의 코드·이미지·문구를 복사하지 않는다.
-   프레임워크·애니메이션 라이브러리를 추가하지 않는다(스택 유지).
-   폰트는 범위 밖이다.

-   화면 전환 참고 사이트: `https://guitar-riff.pages.dev/`

## 5. 완료 확인 방법 --- 사용자 결정 (2026-09-13)

-   방문자가 홈에서 무슨 앱인지 바로 알 수 있다.
-   홈·demo·가나 학습은 서버 요청 0건이다.
-   홈·demo·가나 학습 route가 `api.ts`, `endpoints.ts`, `env.ts`를 transitively import하지 않는다.
-   상단 `로그인`을 누를 때만 로그인 상태를 확인한다. 홈을 열 때는 확인하지 않는다.
-   API 서버가 꺼져 있어도 홈·demo·가나 학습은 멀쩡하다.
-   로그인 실패 문구는 사유를 가르지 않는 한 문구다.
-   `prefers-reduced-motion`이면 움직임이 최소화된다.

정식 합격 기준은 Wave 1의 `spec/mvp-02-onboarding/13_ACCEPTANCE_CRITERIA.md`다.
