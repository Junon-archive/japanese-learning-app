# ADR-006 --- Online Brute-Force Defense

Status: Accepted

Decision: `POST /api/auth/login`의 온라인 무차별 대입 방어를 **password
엔트로피 하한(최소 16 code point, 계정 생성 경로에서 강제)** 으로 둔다.
애플리케이션 레벨 rate limit·계정 잠금·실패 지연을 MVP에 두지 않는다.
배포 계층(Cloudflare) rate limit은 권장하되 **운영자 책임**으로 명시하고
켜져 있다고 가정하지 않는다. canonical 정의는
`spec/04_SECURITY_AND_DATA.md`의 `Password 요구사항 (MVP 확정)`과
`온라인 무차별 대입 방어 (MVP 확정)`에 있다.

명세에는 "단순하고 안전한 개인 로그인"만 있었고 무차별 대입에 대한 요구가
**없었다**(`brute` / `시도 제한` 검색 결과 0건). 구현이 명세를 어긴 것이
아니라 명세에 요구가 없었다.

## 실측 조건

``` text
계정             1개, public signup 없음, login_id는 추측 가능
노출             Cloudflare Tunnel로 인터넷 공개
Argon2id 비용     요청당 약 39ms (argon2-cffi 기본 파라미터 측정값)
시도율            단일 스레드 약 25/초 = 약 2.2e6/일
Origin 검증       브라우저 CSRF만 막는다. curl은 Origin 헤더를 위조한다
```

즉 password가 약하면 **오프라인이 아니라 온라인으로** 뚫린다. 부족한 것은
시도 속도 제한이 아니라 탐색 공간이다. 위 시도율에서 password manager가
생성한 16자 난수는 전수 탐색이 불가능하고, 반대로 rate limit은 약한
password의 수명을 늘릴 뿐이다.

## 버린 대안

-   **계정 잠금(lockout)**: 계정이 하나뿐이라 잠금은 곧 주인에 대한
    DoS다. 공격자가 일부러 틀리기만 하면 정당한 사용자가 잠기고, 해제
    경로를 만들면 그 경로가 새 공격 표면이 된다.
-   **DB 기반 실패 카운터**: 새 테이블/컬럼 + migration + 정리 작업이
    필요하고, 인증되지 않은 요청마다 write 경로가 열려 공격자가 DB 쓰기를
    유발할 수 있다. 엔트로피 하한이 온라인 추측을 이미 무의미하게 만든
    뒤에 치르기에는 비싼 값이다.
-   **in-process 메모리 카운터**: worker 프로세스 수에 따라 실제 한도가
    달라지고 재시작하면 사라진다. 정확한 값을 보장하지 못하는 상태를 인증
    경로에 새로 만들지 않는다.
-   **Redis 기반 rate limit**: MVP는 Redis를 쓰지 않는다(ADR-001). 이
    기능 하나를 위해 인프라 구성요소를 늘리지 않는다.
-   **배포 계층에만 의존**: 외부 서비스 설정이라 명세·코드·테스트로 강제할
    수단이 없다. 그것만 믿으면 "설정을 잊으면 무방비"가 되므로 1차 방어를
    운영자 설정에 의존하지 않는 password 하한에 둔다.

## password 하한을 16으로 잡은 이유

실사용자가 1명이고 계정 생성이 CLI 1회라 UX 비용이 사실상 0이다. public
signup이 있는 서비스라면 일반적인 하한(8)과의 차이를 논해야 하지만 여기서는
높게 잡아도 치르는 비용이 없다. 복잡도 혼용 규칙, 금지어 목록, 유출
password 조회는 각각 예측 가능한 변형 유도, wordlist 의존성, 외부 네트워크
호출을 만들어 이익보다 비용이 크므로 두지 않는다.

## 값의 위치

최소 길이는 학습 정책 YAML(`14_CONFIGURATION.md`)에도 `.env`에도 두지
않고 코드에 고정한다. 실사용 후 튜닝하는 학습값이 아니고, 환경변수로 두면
보안 하한을 낮추는 스위치가 생긴다. `Secure` cookie 플래그를 끄는 스위치를
만들지 않기로 한 것과 같은 판단이다(ADR-004).

## 한계

-   길이 하한은 엔트로피를 측정하지 못한다. 16자짜리 저엔트로피
    password(`junon1234567890`)는 통과한다. 이 간극은 기계 검증이 아니라
    "password manager 난수 또는 diceware 4단어 이상"이라는 운영 규칙이
    메운다.
-   배포 계층 rate limit을 설정하지 않으면 login endpoint는 초당 수십 회의
    추측 시도를 그대로 받는다. 남는 방어는 password 하한과 Argon2id
    비용뿐이며, 이 사실을 명세에 드러내 둔다.
-   익명 login endpoint가 요청당 Argon2id 메모리를 잡는 자원 고갈 위험은
    **수용된 위험**으로 기록했다. 내용과 재검토 조건은
    `spec/04_SECURITY_AND_DATA.md`의
    `수용된 위험 --- login endpoint의 메모리 비용`이 canonical이다.
-   로그인 실패를 관측할 수단이 MVP에 없다. 실패마다 로그를 남기면 위
    시도율에서 로그 자체가 디스크 압박이 되므로 관측·알림은 Future다.

## 다시 열어야 하는 조건

사용자가 2명 이상이 되거나, public signup이 생기거나, password 하한을
낮추거나, 로그인 실패 관측 수단이 생기면 이 결정을 다시 검토한다.
